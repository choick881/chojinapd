# 배포 자동화 가이드 (clasp)

지금은 Apps Script 편집기에 코드를 **복사·붙여넣기**해서 배포합니다. 아래처럼 바꾸면 GitHub에 있는 코드를 명령 한 줄로 올리고 배포할 수 있습니다.

```
GitHub 저장소 ──(npm test 통과)──> clasp push ──> clasp deploy (URL 그대로)
```

## 처음 한 번만 준비

모두 **부서 공동계정**으로 진행합니다. PC에 Node.js 18 이상이 있어야 합니다.

1. https://script.google.com/home/usersettings 에서 **Google Apps Script API**를 **사용**으로 바꿉니다.
2. 저장소를 내려받고 도구를 설치합니다.
   ```bash
   git clone https://github.com/choick881/chojinapd.git
   cd chojinapd/hyflip
   npm install
   npx clasp login          # 브라우저가 열리면 부서 공동계정으로 로그인
   ```
3. 스크립트 ID를 넣습니다.
   - 데이터 시트에서 **확장 프로그램 > Apps Script > ⚙ 프로젝트 설정 > 스크립트 ID**를 복사합니다.
   - `.clasp.json.example`을 `.clasp.json`으로 복사하고 `scriptId`에 붙여넣습니다.
4. 웹 앱 배포 ID를 확인합니다.
   ```bash
   npx clasp deployments    # "@숫자 - 설명" 줄의 AKfy... 값이 배포 ID
   ```
   `@HEAD`가 아닌 웹 앱 배포 ID를 고르세요. 이 ID로 갱신해야 URL이 바뀌지 않습니다.

> `.clasp.json`과 로그인 정보(`~/.clasprc.json`)는 `.gitignore`에 들어 있어 GitHub에 올라가지 않습니다.

## 배포할 때마다

```bash
cd chojinapd/hyflip
git pull
HYFLIP_DEPLOYMENT_ID=AKfy...배포ID npm run deploy -- "v1.0.2 대리신청 삭제"
```

스크립트가 하는 일:

1. 문법 검사와 자동 테스트 25개를 돌립니다. 하나라도 실패하면 멈춥니다.
2. **확인을 받은 뒤** Apps Script 프로젝트의 코드를 `src/` 내용으로 덮어씁니다(`clasp push`).
3. **한 번 더 확인을 받은 뒤** 기존 웹 앱을 새 버전으로 갱신합니다(`clasp deploy -i`). URL은 그대로입니다.

배포 후 Apps Script 편집기에서 `setup`을 한 번 실행해 "설치 완료: 트리거 2개"를 확인하세요. 트리거는 중복으로 생기지 않습니다.

## 주의할 점

- **`appsscript.json`도 함께 올라갑니다.** 시간대(서울), V8, 웹 앱 설정(실행 사용자 = 나, 액세스 = 도메인)이 들어 있습니다. 편집기에서 바꾼 설정이 있으면 이 파일에 먼저 반영하세요.
- **편집기에서 직접 고친 코드는 push 때 사라집니다.** 앞으로 코드 수정은 저장소에서만 하세요. 편집기에서 급히 고쳤다면 `npx clasp pull`로 먼저 가져와 커밋하세요.
- **시트 내용은 건드리지 않습니다.** clasp는 스크립트만 다룹니다. 탭·열·메일 문구는 여전히 시트에서 직접 관리합니다.

## 다음 단계로 고려할 것 (선택)

- **GitHub Actions 자동 배포:** `main`에 합쳐지면 자동으로 push·deploy하게 만들 수 있습니다. 다만 부서 공동계정의 로그인 토큰을 GitHub 비밀값으로 보관해야 하므로, 보안 정책을 확인한 뒤 결정하는 것을 권합니다. 지금은 테스트만 자동으로 돌고, 배포는 사람이 위 명령으로 합니다.
- **테스트용 사본 배포:** 데이터 시트 사본 + 별도 스크립트 ID를 하나 더 두면, 실제 신청 페이지를 건드리지 않고 12/4 내부 테스트를 할 수 있습니다.
